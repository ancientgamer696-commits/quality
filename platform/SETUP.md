# Quality Glass Emporium — step-by-step Cloudflare connection

**Status:** This workspace contains two buildable **Pages demo sites** and a **read-only Worker API foundation**. No account is linked, no domain is purchased, no real order/payment/screenshot is collected. The manager site is a **public sample UI, not an admin login**. Do **not** put real customer information or banking data into either preview.

## Stage 1 — publish both safe demos to free `pages.dev` URLs

The shop and manager HTML files are already in this repository. `scripts/build.py` outputs two Pages folders (`apps/shop/dist`, `apps/manager/dist`). The shop **published output disables checkout** on purpose until backend/auth/private proof storage exist. The manager explicitly shows fictional data.

**Recommended if you do not have GitHub yet: Cloudflare Pages Direct Upload.** Pages lets you drag and drop prebuilt folders or ZIPs in the dashboard. [Cloudflare Direct Upload instructions](https://developers.cloudflare.com/pages/get-started/direct-upload/). No custom domain is required.

1. Make a Cloudflare account you control: <https://dash.cloudflare.com/sign-up/workers-and-pages>. Do not share password, recovery codes or tokens. Verify email and enable account 2FA.
2. Download the already-prepared ZIP files: [`quality-glass-shop-pages-upload.zip`](quality-glass-shop-pages-upload.zip) and [`quality-glass-manager-preview-pages-upload.zip`](quality-glass-manager-preview-pages-upload.zip). Each ZIP has `index.html` and `_headers` at its root. They were built and tested in this workspace. For later changes, run `npm run build` and rebuild both ZIPs before redeploying. Generated `dist/` directories are excluded from persistent workspace snapshots; the ZIPs are saved here deliberately.
3. In Cloudflare dashboard go to **Workers & Pages → Create application → Get started → Drag and drop your files**. Create **`quality-glass-shop`** (or a unique name), upload the **shop ZIP**, and deploy. Your assigned URL will be like `quality-glass-shop.pages.dev` (exact name can differ if occupied).
4. Repeat for the **manager ZIP** as a **separate project** named **`quality-glass-manager-preview`**. The manager demo is publicly accessible at its Pages URL: **not** a real private admin panel. Never label it as production admin until server-side auth is implemented.
5. Record your **exact two Pages URLs**. No need to publish your account ID or any secret. Check homepage, collections, featured/deals; check that deployed shop checkout says **“Checkout unavailable in public preview.”** If it doesn't, **stop and rebuild** from this project rather than uploading the earlier standalone demo.

**Alternative for automatic updates:** commit `quality-glass-platform` to your own GitHub repo, then connect **two** Pages projects to the same repo. Shop project root directory: `apps/shop`; build command: `npm run build`; output directory: `dist`. Manager project root directory: `apps/manager`; build command: `npm run build`; output directory: `dist`. Each `package.json` calls the shared Python build script two directories above its root; for reliable monorepo builds we instead recommend root directory = repo root, build commands `python3 scripts/build.py shop` and `python3 scripts/build.py manager`, output directories `apps/shop/dist` and `apps/manager/dist` respectively. Do not mix root-relative and app-relative output paths. Confirm the builder image has Python 3. Git integration automatically deploys pushes; Direct Upload projects do not automatically convert to Git-integrated projects. [Cloudflare Git integration](https://developers.cloudflare.com/pages/get-started/git-integration/).

**CLI option after signing in locally:** `npx wrangler login` then from project root `npx wrangler pages project create quality-glass-shop`; `npx wrangler pages project create quality-glass-manager-preview`; deploy using `npx wrangler pages deploy apps/shop/dist --project-name=quality-glass-shop` and similarly for `apps/manager/dist`. CLI requires authentication from a browser you control; don't run login on a shared/public session or paste the credentials here. If the exact name is unavailable, use the real project name in deploy command. Direct Upload supported by Cloudflare's Wrangler CLI. [Cloudflare Direct Upload docs](https://developers.cloudflare.com/pages/get-started/direct-upload/).

## Stage 2 — Worker API / D1 (development only)

1. From project root, run `npm install`, `npm test`. Wrangler now requires Node 22+; this repo pins an npm-distributed Node 22 binary and uses it for the Wrangler npm scripts, so the local environment's Node 20 can still run tests/builds. The Worker at `apps/api/src/index.mjs` supports public `GET /health`, `GET /api/v1/categories`, `GET /api/v1/products`. It has **no write/admin routes** and will return `503 DB_NOT_CONFIGURED` on catalog requests until a D1 binding is added. The two HTML previews do not call this Worker yet.
2. Test Worker locally using `npm run dev:api` and fetch `/health`. This does not require production credentials. `wrangler dev` can prompt for a Cloudflare sign-in depending on environment. Default port is 8787. [Cloudflare Workers setup](https://developers.cloudflare.com/workers/get-started/guide/).
3. Once you are signed in to the **right Cloudflare account**, create a **development** D1 database (for example `quality-glass-data-dev`) from dashboard or from project root `npx wrangler d1 create quality-glass-data-dev --config apps/api/wrangler.jsonc`. Copy only the **non-secret D1 database ID** from Cloudflare into `apps/api/wrangler.jsonc` in a `d1_databases` array with `binding: "DB"`, `database_name: "quality-glass-data-dev"`, and your real `database_id`. Check the binding in the dashboard; do not use a fake ID. [Cloudflare D1 setup](https://developers.cloudflare.com/d1/get-started/).
4. The migration is at `apps/api/migrations/0001_catalog.sql`. Wrangler finds migrations under the Worker config root (`apps/api/migrations`). Apply **local first**: `npx wrangler d1 migrations apply quality-glass-data-dev --local --config apps/api/wrangler.jsonc`. When validated, apply to the **development remote** database only: `npx wrangler d1 migrations apply quality-glass-data-dev --remote --config apps/api/wrangler.jsonc`. Never run remote changes against a live production DB without backups and a review.
5. Do **not** publish sample artwork/prices into D1 as real stock. The schema has zero published products by default. Deploy the Worker only if you want a public **read-only development API**: `npx wrangler deploy --config apps/api/wrangler.jsonc`. It gets an assigned `workers.dev` hostname once that subdomain is enabled. This Worker has no private data yet.
6. Set `ALLOWED_ORIGINS` to the **actual** shop and manager origins (comma-separated, e.g. `https://quality-glass-shop.pages.dev,https://quality-glass-manager-preview.pages.dev`) in the Worker config and redeploy. No wildcard CORS. Do not insert the Worker URL into the public HTML until both sides share validated types/data and admin auth is ready.

## Stage 3 — application security and actual data (future steps)

We will move the UI out of static HTML into a real frontend consuming the Worker. First add owner Google sign-in or another reliable login with **server-side allowlist/RBAC**, secure sessions and audited admin endpoints. Then add actual products, owner-approved prices, quote rules, cart/orders, storage and proof review. A free `.pages.dev` origin for each site plus a Worker `.workers.dev` origin means **cross-origin** browser requests: strict CORS and safe auth are necessary. No production manager action can be protected by hiding buttons in the HTML.

**Payment flow gate:** owner provides a verified merchant UPI QR/ID, checkout quotes final shipping/tax, and 2+ frames receive an approved combined quote before payment. UTR/screenshot are **pending evidence**, not verification; staff checks merchant account. Private payment screenshot upload goes to protected object storage and is never sent via public URLs or stored in D1 as binary. WhatsApp prefilled text opens a draft; a customer still must press Send and attach any screenshot manually.
